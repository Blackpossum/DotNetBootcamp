## The problem generics solve

Without generics you'd either write a `IntStack`, `StringStack`, `CustomerStack`… (copy-paste hell) or an `object`-based stack (no type safety, boxing costs). Generics give **one implementation, checked per-use at compile time**:

```csharp
public class Stack<T>                    // T = type parameter
{
    private readonly List<T> _items = [];
    public void Push(T item) => _items.Add(item);
    public T Pop()
    {
        if (_items.Count == 0) throw new InvalidOperationException("empty");
        T top = _items[^1];
        _items.RemoveAt(_items.Count - 1);
        return top;
    }
}

var ints = new Stack<int>();      // a stack OF INTS — Push("x") is a compile error
var names = new Stack<string>();
```

The runtime specializes generic code: value-type instantiations (`Stack<int>`) get their own compiled code with **no boxing**; reference types share one implementation. You get abstraction *without* paying for it — the reason .NET collections are fast.

## Generic methods

Methods can have their own type parameters, usually **inferred** from arguments:

```csharp
public static T FirstOrFallback<T>(IEnumerable<T> source, T fallback)
{
    foreach (var item in source) return item;
    return fallback;
}

int first = FirstOrFallback(new[] { 1, 2, 3 }, -1);       // T=int inferred — no angle brackets needed
string s = FirstOrFallback(Array.Empty<string>(), "none");
```

Multiple parameters compose naturally:

```csharp
public static Dictionary<TKey, List<TItem>> GroupInto<TKey, TItem>(
    IEnumerable<TItem> items, Func<TItem, TKey> keyOf) where TKey : notnull
{
    var result = new Dictionary<TKey, List<TItem>>();
    foreach (var item in items)
    {
        TKey key = keyOf(item);
        if (!result.TryGetValue(key, out var bucket))
            result[key] = bucket = [];
        bucket.Add(item);
    }
    return result;
}
```

## Constraints: telling the compiler what T can do

Inside generic code you can only use members the compiler *knows* `T` has — which by default is almost nothing. **Constraints** unlock capabilities:

```csharp
where T : IComparable<T>      // can call CompareTo → sorting/max algorithms
where T : new()               // can do new T()
where T : class               // reference types only (enables null checks)
where T : struct              // value types only (used by Nullable<T> itself)
where T : notnull             // no nullable types — required for dictionary keys
where T : SomeBase            // must derive from SomeBase
where T : IShape, IPrintable  // multiple interface constraints combine
```

```csharp
public static T Max<T>(IEnumerable<T> source) where T : IComparable<T>
{
    T best = source.First();
    foreach (var x in source.Skip(1))
        if (x.CompareTo(best) > 0) best = x;
    return best;
}
```

### Generic math — the modern flex (know it exists)

.NET 7+ interfaces like `INumber<T>` use **static abstract members** so algorithms can use `+`, `0`, `Parse` generically:

```csharp
public static T Sum<T>(IEnumerable<T> xs) where T : System.Numerics.INumber<T>
{
    T total = T.Zero;
    foreach (var x in xs) total += x;
    return total;
}
// works for int, double, decimal, BigInteger, your own vector type…
```

## Variance in 90 seconds (`out`/`in` on interfaces)

`IEnumerable<out T>` is **covariant**: an `IEnumerable<Circle>` may be used where `IEnumerable<Shape>` is expected (read-only positions are safe). `Action<in T>` is **contravariant**: an `Action<Shape>` can stand in for `Action<Circle>`. Lists are invariant — `List<Circle>` is *not* a `List<Shape>` (you could sneak a Square in). You mostly *consume* variance; recognizing the error message is the skill.

### Step 1 — a typed Result (the error-handling workhorse)

```csharp
public readonly record struct Result<T>
{
    public bool Success { get; }
    public T? Value { get; }
    public string Error { get; }

    private Result(bool ok, T? value, string error) => (Success, Value, Error) = (ok, value, error);

    public static Result<T> Ok(T value) => new(true, value, "");
    public static Result<T> Fail(string error) => new(false, default, error);

    public T OrElse(T fallback) => Success ? Value! : fallback;
}
```

```csharp
static Result<int> ParseAge(string raw)
    => int.TryParse(raw, out int age) && age is >= 0 and <= 130
        ? Result<int>.Ok(age)
        : Result<int>.Fail($"'{raw}' is not a valid age");

Console.WriteLine(ParseAge("34").OrElse(-1));       // 34
Console.WriteLine(ParseAge("abc").Error);           // 'abc' is not a valid age
```

One generic type now standardizes success/failure across your whole codebase — you'll meet richer versions of this in every serious C# codebase.

### Step 2 — a constrained algorithm

```csharp
static (T Min, T Max) Bounds<T>(IEnumerable<T> xs) where T : IComparable<T>
{
    using var e = xs.GetEnumerator();
    if (!e.MoveNext()) throw new ArgumentException("empty sequence");
    T min = e.Current, max = e.Current;
    while (e.MoveNext())
    {
        if (e.Current.CompareTo(min) < 0) min = e.Current;
        if (e.Current.CompareTo(max) > 0) max = e.Current;
    }
    return (min, max);
}

Console.WriteLine(Bounds(new[] { 3, 9, 1, 7 }));                    // (1, 9)
Console.WriteLine(Bounds(new[] { "pear", "apple", "fig" }));        // (apple, pear)
Console.WriteLine(Bounds(new[] { new DateOnly(2026,1,1), new DateOnly(2025,5,5) }));
```

One implementation, three element types — and try `Bounds(new[] { new object() })`: the *compile-time* error names the missing constraint. That's generics' promise: errors before running.

Temporarily delete `where T : IComparable<T>` — `CompareTo` turns red immediately: without constraints, T only has `object`'s members. Restore it.

### Step 4 — a generic cache with two parameters + factory

```csharp
public class Cache<TKey, TValue> where TKey : notnull
{
    private readonly Dictionary<TKey, TValue> _store = [];
    public int Hits { get; private set; }
    public int Misses { get; private set; }

    public TValue GetOrAdd(TKey key, Func<TKey, TValue> factory)
    {
        if (_store.TryGetValue(key, out var hit)) { Hits++; return hit; }
        Misses++;
        return _store[key] = factory(key);
    }
}
```

```csharp
var squares = new Cache<int, long>();
for (int i = 0; i < 5; i++)
    Console.WriteLine(squares.GetOrAdd(i % 3, k => { Console.WriteLine($"  computing {k}²"); return (long)k * k; }));
Console.WriteLine($"hits {squares.Hits}, misses {squares.Misses}");   // 2 hits, 3 misses
```

`Func<TKey, TValue>` is a *delegate* — a function passed as data. Perfect segue to the next lesson.

### Step 5 — generic math taste

```csharp
using System.Numerics;

static T Average<T>(IEnumerable<T> xs) where T : INumber<T>
{
    T sum = T.Zero; T count = T.Zero;
    foreach (var x in xs) { sum += x; count++; }
    return sum / count;
}

Console.WriteLine(Average(new[] { 1, 2, 3, 4 }));            // 2 (int division!)
Console.WriteLine(Average(new[] { 1.0, 2.0, 3.0, 4.0 }));    // 2.5
Console.WriteLine(Average(new[] { 1m, 2m, 3m, 4m }));        // 2.5 exactly
```

Same algorithm; each numeric type keeps its own semantics (spot the int-division callback!).

## Challenge: `Repository<T>` — generic storage with constraints

Build the abstraction you'll later see EF Core play out at production scale.

### Requirements

1. Interface `IEntity { string Id { get; } }`; sample records `Customer(string Id, string Name)` and `Product(string Id, string Name, decimal Price)` implementing it.
2. Class `Repository<T> where T : IEntity`:
   - `void Upsert(T entity)`, `Result<T> Get(string id)` (reuse the tutorial's `Result<T>`!), `bool Delete(string id)`, `IReadOnlyCollection<T> All { get; }`
   - `IEnumerable<T> Where(Func<T, bool> predicate)` — filter with a passed-in function
3. Generic method (not on the class) `static void Seed<T>(Repository<T> repo, params T[] items) where T : IEntity`.
4. Demonstrate: seed both repositories, a hit + a miss through `Result<T>`, a `Where` over products (`p => p.Price > 10`), and a compile-time proof that `Repository<string>` is rejected (leave it in a comment with the error text).
5. Stretch: add `Repository<T>.Update(string id, Func<T, T> mutate)` that fetches, applies the function, and stores the result — records + `with` at the call site.

:::solution Show solution
```csharp
public interface IEntity { string Id { get; } }

public record Customer(string Id, string Name) : IEntity;
public record Product(string Id, string Name, decimal Price) : IEntity;

public class Repository<T> where T : IEntity
{
    private readonly Dictionary<string, T> _store = [];

    public void Upsert(T entity) => _store[entity.Id] = entity;

    public Result<T> Get(string id)
        => _store.TryGetValue(id, out var e)
            ? Result<T>.Ok(e)
            : Result<T>.Fail($"{typeof(T).Name} '{id}' not found");

    public bool Delete(string id) => _store.Remove(id);

    public IReadOnlyCollection<T> All => _store.Values;

    public IEnumerable<T> Where(Func<T, bool> predicate)
    {
        foreach (var e in _store.Values)
            if (predicate(e)) yield return e;
    }

    public Result<T> Update(string id, Func<T, T> mutate)
    {
        var found = Get(id);
        if (!found.Success) return found;
        T updated = mutate(found.Value!);
        if (updated.Id != id) return Result<T>.Fail("Update must not change Id");
        Upsert(updated);
        return Result<T>.Ok(updated);
    }
}

public static class RepositoryTools
{
    public static void Seed<T>(Repository<T> repo, params T[] items) where T : IEntity
    {
        foreach (var item in items) repo.Upsert(item);
    }
}
```

```csharp
var customers = new Repository<Customer>();
var products = new Repository<Product>();

RepositoryTools.Seed(customers, new("c1", "Ada"), new("c2", "Grace"));
RepositoryTools.Seed(products,
    new("p1", "Keyboard", 49.99m), new("p2", "Mouse", 19.99m), new("p3", "Cable", 4.99m));

Console.WriteLine(customers.Get("c1").Value);                    // Customer { Id = c1, Name = Ada }
Console.WriteLine(customers.Get("c9").Error);                    // Customer 'c9' not found

foreach (var p in products.Where(p => p.Price > 10))
    Console.WriteLine(p);

var renamed = customers.Update("c1", c => c with { Name = "Ada Lovelace" });
Console.WriteLine(renamed.Value);

// var bad = new Repository<string>();
// ❌ CS0311: The type 'string' cannot be used as type parameter 'T' …
//    There is no implicit reference conversion from 'string' to 'IEntity'.
```

The constraint turns "you can only store entities" from documentation into physics. `Where(Func<T,bool>)` + `Update(Func<T,T>)` preview the function-as-data style the next lesson makes precise — and `yield return` gives lazy evaluation, which LINQ will formalize.
:::

## Functions as data

A **delegate** is a type whose values are *methods*. Storing a method in a variable, passing it, returning it — that's the whole trick, and it powers LINQ, events, callbacks, and DI factories.

You'll almost always use the two built-in generic families instead of declaring your own:

```csharp
Func<int, int, int> add = (a, b) => a + b;      // Func<…, TResult>: RETURNS the last type param
Func<string, bool> isLong = s => s.Length > 10; // 1 input → bool (a "predicate")
Func<double> roll = () => Random.Shared.NextDouble();   // no inputs

Action<string> log = msg => Console.WriteLine($"[{DateTime.Now:HH:mm}] {msg}");  // Action: returns void
Action beep = Console.Beep;                     // a METHOD GROUP converts directly

int r = add(3, 4);                              // invoke like a method
```

## Lambda expressions — the syntax spectrum

```csharp
x => x * 2                        // one param, expression body
(a, b) => a + b                   // multiple params
() => 42                          // no params
s => { var t = s.Trim(); return t.ToUpper(); }   // statement body
(int x) => x * 2                  // explicit types when inference needs help
(text, out int n) => int.TryParse(text, out n)   // C# 14: modifiers WITHOUT types now legal
```

### Closures — lambdas capture variables

```csharp
int counter = 0;
Action increment = () => counter++;    // captures the VARIABLE, not a copy
increment(); increment();
Console.WriteLine(counter);            // 2 — the lambda mutated the local!
```

The compiler hoists captured variables into a hidden class so they outlive the method. Two consequences: (1) shared mutable capture across lambdas is a classic bug source — each `for`-loop iteration sharing one variable was *the* legendary gotcha (fixed for `foreach` in C# 5, still true for `for`); (2) captures allocate — hot paths prefer `static` lambdas (`static x => x * 2`), which the compiler verifies capture nothing.

## Higher-order functions — the pattern behind LINQ

```csharp
static List<T> Filter<T>(IEnumerable<T> source, Func<T, bool> keep)
{
    List<T> result = [];
    foreach (var x in source)
        if (keep(x)) result.Add(x);
    return result;
}

var evens = Filter(numbers, n => n % 2 == 0);
var short_ = Filter(names, n => n.Length <= 4);
```

One `Filter` handles every filtering rule forever, because *the rule is a parameter*. Next lesson you'll see this exact signature — as LINQ's `Where`.

## Events: delegates with a safety protocol

An **event** is a multicast delegate field that outsiders can only subscribe to (`+=`) or unsubscribe from (`-=`) — never invoke or overwrite:

```csharp
public class Downloader
{
    public event EventHandler<int>? ProgressChanged;      // int = percent
    public event EventHandler? Completed;

    public void Run()
    {
        for (int pct = 0; pct <= 100; pct += 25)
        {
            Thread.Sleep(100);
            ProgressChanged?.Invoke(this, pct);           // ?. because no subscribers = null
        }
        Completed?.Invoke(this, EventArgs.Empty);
    }
}
```

```csharp
var dl = new Downloader();
dl.ProgressChanged += (_, pct) => Console.Write($"\r{pct}%   ");
dl.ProgressChanged += (_, pct) => File.AppendAllText("log.txt", $"{pct}\n");   // multicast: BOTH run
dl.Completed += (_, _) => Console.WriteLine("\ndone!");
dl.Run();
```

Conventions worth following: `EventHandler`/`EventHandler<TArgs>` signature (sender + args), null-conditional invoke, past-tense names (`Completed`), and **unsubscribe when done** — a subscriber referenced by a long-lived publisher can't be garbage-collected (the classic "event memory leak").

:::note Delegates vs interfaces
A single-method interface (`IComparer<T>`) and a delegate (`Comparison<T>`) solve the same problem. Delegates win for lightweight, one-off behavior (lambdas!); interfaces win when the behavior has state, multiple methods, or deserves a name. .NET APIs frequently offer both.
:::

```csharp
var actions = new List<Action>();

    actions.Add(() => Console.Write($"{i} "));
```

### Step 4 — the stock ticker (events)

```csharp
public class StockTicker
{
    private readonly Dictionary<string, decimal> _prices = [];
    public event EventHandler<(string Symbol, decimal Old, decimal New)>? PriceChanged;

    public void Update(string symbol, decimal price)
    {
        decimal old = _prices.GetValueOrDefault(symbol, price);
        _prices[symbol] = price;
        if (old != price)
            PriceChanged?.Invoke(this, (symbol, old, price));
    }
}
```

```csharp
var ticker = new StockTicker();

ticker.PriceChanged += (_, e) =>
    Console.WriteLine($"{e.Symbol}: {e.Old} → {e.New} ({(e.New - e.Old) / e.Old:P1})");

EventHandler<(string Symbol, decimal Old, decimal New)> alarm = (_, e) =>
{
    if (Math.Abs((e.New - e.Old) / e.Old) > 0.05m)
        Console.WriteLine($"  🚨 {e.Symbol} moved more than 5%!");
};
ticker.PriceChanged += alarm;

ticker.Update("MSFT", 500m);
ticker.Update("MSFT", 512m);      // logger fires
ticker.Update("MSFT", 460m);      // logger AND alarm fire

ticker.PriceChanged -= alarm;     // unsubscribe — leak prevention habit
ticker.Update("MSFT", 400m);      // only the logger now
```

Two independent subscribers, added and removed at runtime, publisher knows nothing about them: the observer pattern, natively.

## Challenge: a validation engine

Build a reusable, composable validator library — delegates as first-class design material.

### Requirements

1. `public delegate (bool Ok, string? Error) Rule<T>(T value);` — a custom delegate type (practice declaring one).
2. Static class `Rules` with factory methods returning `Rule<string>`:
   - `NotEmpty()`, `MaxLen(int n)`, `Matches(string pattern, string description)` (use `Regex.IsMatch`), and generic `Custom<T>(Func<T, bool> test, string error)`.
   Factories returning configured lambdas = closures doing honest work.
3. `Validator<T>` class: `Add(Rule<T> rule)` (fluent — return `this`), `List<string> Validate(T value)` running all rules and collecting errors.
4. An event on the validator: `event Action<T, string>? RuleFailed;` raised per failure — subscribe a logger in the demo.
5. Demo: an email validator (not empty, ≤ 60 chars, matches something like `^[^@\s]+@[^@\s]+\.[^@\s]+$`) run against 4 samples including edge cases; print per-sample verdicts plus the event-driven failure log.

:::solution Show solution
```csharp
using System.Text.RegularExpressions;

public delegate (bool Ok, string? Error) Rule<T>(T value);

public static class Rules
{
    public static Rule<string> NotEmpty()
        => v => string.IsNullOrWhiteSpace(v) ? (false, "must not be empty") : (true, null);

    public static Rule<string> MaxLen(int n)
        => v => v.Length > n ? (false, $"longer than {n} chars") : (true, null);

    public static Rule<string> Matches(string pattern, string description)
        => v => Regex.IsMatch(v, pattern) ? (true, null) : (false, $"is not a valid {description}");

    public static Rule<T> Custom<T>(Func<T, bool> test, string error)
        => v => test(v) ? (true, null) : (false, error);
}

public class Validator<T>
{
    private readonly List<Rule<T>> _rules = [];
    public event Action<T, string>? RuleFailed;

    public Validator<T> Add(Rule<T> rule)
    {
        _rules.Add(rule);
        return this;                       // fluent chaining
    }

    public List<string> Validate(T value)
    {
        List<string> errors = [];
        foreach (var rule in _rules)
        {
            var (ok, error) = rule(value);
            if (!ok)
            {
                errors.Add(error!);
                RuleFailed?.Invoke(value, error!);
            }
        }
        return errors;
    }
}
```

```csharp
var email = new Validator<string>()
    .Add(Rules.NotEmpty())
    .Add(Rules.MaxLen(60))
    .Add(Rules.Matches(@"^[^@\s]+@[^@\s]+\.[^@\s]+$", "email address"))
    .Add(Rules.Custom<string>(v => !v.EndsWith(".test"), "test domains not allowed"));

email.RuleFailed += (value, error) =>
    Console.WriteLine($"    [audit] '{value}' → {error}");

string[] samples = ["ada@example.com", "", "not-an-email", "user@domain.test"];
foreach (var s in samples)
{
    var errors = email.Validate(s);
    Console.WriteLine(errors.Count == 0
        ? $"✔ '{s}'"
        : $"✘ '{s}': {string.Join("; ", errors)}");
}
```

Study what each factory returns: a lambda *closing over* the factory's parameters (`n`, `pattern`) — configuration frozen into behavior. The fluent Add + event + delegate collection is, structurally, how FluentValidation (the dominant .NET validation library) works inside.

> The event keyword locks down the delegate: outsiders can't invoke it, clear it, or overwrite other subscribers — the encapsulation that makes the observer pattern safe.

? Why can forgotten event subscriptions cause memory leaks?
- Delegates are unmanaged resources
* The publisher's delegate holds a reference to the subscriber, keeping it alive as long as the publisher lives
- Events allocate on every invoke
- The GC can't scan delegates
> A long-lived publisher (static, app-wide service) referencing a short-lived subscriber pins it in memory. Unsubscribe (-=) when the subscriber's lifetime ends.

? A `static` lambda (`static x => x * 2`)…
- Can only call static methods
* Is compiler-verified to capture nothing, avoiding closure allocations
- Runs at compile time
- Is required in LINQ
> The static modifier on lambdas forbids captures — a performance tool for hot paths and a documentation of intent.

## Deferred execution — the concept that separates juniors from seniors

A LINQ query is a **description**, not a result. Nothing runs until you enumerate:

```csharp
var query = nums.Where(n => { Console.Write($"test:{n} "); return n > 2; });
// nothing printed yet!

foreach (var n in query) { }    // NOW the tests print
foreach (var n in query) { }    // …and print AGAIN — the query re-executes!
```

Consequences:

1. **Queries see current data** — filter defined before an `Add` still includes the added item when enumerated later.
2. **Multiple enumeration = repeated work** (or repeated DB hits in EF!). Materialize with `ToList()` when you'll reuse results.
3. **Infinite sequences work** — `Enumerable.Range`, generators with `yield return`, `.Take(10)` at the end.

Under the hood, `Where`/`Select` build chained iterator objects using `yield return` machinery — a pull pipeline where each element flows through the whole chain one at a time (that's why `First()` after `Where` can stop the entire pipeline early).

:::tip Query syntax exists too
`from p in people where p.Age > 30 select p.Name` compiles to the same method calls. Method syntax is dominant in modern codebases (better tooling composition); read query syntax fluently, write whichever your team prefers — mixed is fine.
:::

## Extension methods: adding members you don't own

An **extension method** is a static method that *call-sites* treat as an instance method of its first parameter (marked `this`):

```csharp
public static class StringExtensions
{
    public static string Truncate(this string s, int max)
        => s.Length <= max ? s : s[..max] + "…";

    public static bool IsBlank(this string? s) => string.IsNullOrWhiteSpace(s);
}
```

```csharp
"a very long headline".Truncate(10);    // "a very lon…"
"  ".IsBlank();                          // true — extensions even work via null-ish receivers
```

Rules that matter:

- Must live in a **static class**, method **static**, first param marked **`this`**.
- Brought into scope by the namespace's `using` — no using, no extension.
- **Instance methods always win** over extensions with the same signature.
- It's sugar: compiles to a plain static call `StringExtensions.Truncate(s, 10)`. The receiver can even be null (no NullReferenceException at the *call* — your method decides).

LINQ *is* extension methods — `Where` is an extension on `IEnumerable<T>`, which is why `using System.Linq;` unlocks it (implicit usings do this for you).

## C# 14: extension members — the big upgrade

C# 14 introduces **extension blocks**, which can declare not just methods but **properties**, **static members**, and even **operators** for a type you don't own:

```csharp
public static class EnumerableExtensions
{
    // Extension block over an instance receiver:
    extension<T>(IEnumerable<T> source)
    {
        public bool IsEmpty => !source.Any();                 // extension PROPERTY!

        public IEnumerable<T> WhereNot(Func<T, bool> pred)
            => source.Where(x => !pred(x));
    }

    // Extension block over the TYPE itself (static members):
    extension<T>(IEnumerable<T>)
    {
        public static IEnumerable<T> Of(params T[] items) => items;   // static extension method
    }
}
```

```csharp
List<int> nums = [];
Console.WriteLine(nums.IsEmpty);                    // property syntax on someone else's type!
var seq = IEnumerable<int>.Of(1, 2, 3);             // static member on an INTERFACE!
```

Everything old still works — classic `this`-parameter extensions and new extension blocks compile to compatible static methods and coexist freely.

### Design guidance: when to extend

✅ Great uses: fluent helpers over BCL/library types (`.Truncate`, `.ToSlug`), adapting types you can't modify, LINQ-style operator libraries, discoverability (IntelliSense shows extensions where a static helper would be invisible).

⚠️ Cautions: don't extend `object` (pollutes everything); keep extension namespaces intentional (importing = opting into vocabulary); if you own the type, prefer a real member; behavior needing private state can't be an extension.

```csharp
public static class TimeSpanExtensions
{
    public static string Humanize(this TimeSpan t)
    {
        static string Plural(double n, string unit)
            => $"{(int)n} {unit}{((int)n == 1 ? "" : "s")}";

        if (t < TimeSpan.Zero) t = -t;
        return t switch
        {
            { TotalSeconds: < 60 } => Plural(t.TotalSeconds, "second"),
            { TotalMinutes: < 60 } => Plural(t.TotalMinutes, "minute"),
            { TotalHours: < 24 } => $"{Plural(t.TotalHours, "hour")} {t.Minutes} min",
            _ => $"{Plural(t.TotalDays, "day")} {t.Hours} h"
        };
    }

    public static string Ago(this DateTimeOffset moment)
        => $"{(DateTimeOffset.UtcNow - moment).Humanize()} ago";
}

public static class ListExtensions
{
    extension<T>(List<T> source)
    {
        public T? Middle => source.Count == 0 ? default : source[source.Count / 2];

        public List<T> Shuffled()
        {
            var copy = new List<T>(source);
            for (int i = copy.Count - 1; i > 0; i--)
            {
                int j = Random.Shared.Next(i + 1);
                (copy[i], copy[j]) = (copy[j], copy[i]);
            }
            return copy;
        }
    }

    extension<T>(List<T>)
    {
        public static List<T> Repeated(T item, int count)
            => Enumerable.Repeat(item, count).ToList();
    }
}
```

```csharp

Console.WriteLine(TimeSpan.FromMinutes(5).Humanize());      // 5 minutes
Console.WriteLine(TimeSpan.FromHours(3.5).Humanize());      // 3 hours 30 min
Console.WriteLine(TimeSpan.FromDays(2.2).Humanize());       // 2 days 4 h
Console.WriteLine(DateTimeOffset.UtcNow.AddMinutes(-100).Ago());   // 1 hour 40 min ago

var tickets = List<string>.Repeated("🎟", 5);
Console.WriteLine(tickets.JoinToString(" "));

var nums = Enumerable.Range(1, 10).ToList();
Console.WriteLine($"shuffled: {nums.Shuffled().JoinToString()}");
```

## The full pattern vocabulary

You've been using patterns since Module 2. Here's the complete arsenal, organized:

```csharp
// CONSTANT + RELATIONAL + COMBINATORS
if (x is 0) …
if (x is > 0 and <= 100) …
if (c is 'a' or 'e' or 'i' or 'o' or 'u') …
if (obj is not null) …                      // THE idiomatic null check

// TYPE + DECLARATION
if (obj is string s) …

// PROPERTY patterns — match on shape, arbitrarily nested
if (order is { Status: OrderStatus.Paid, Customer.Country: "ID" }) …
if (s is { Length: > 0 } text) …            // non-empty string, bound to text

// TUPLE/POSITIONAL patterns (deconstruction)

{
    (true, true) => "I", (false, true) => "II",
    (false, false) => "III", (true, false) => "IV"
};

// LIST patterns (C# 11+)
int[] a = [1, 2, 3];
if (a is [1, _, _]) …                        // starts with 1, length 3
if (a is [var first, .. var rest]) …         // head + tail slice
if (a is [.., var last]) …                   // grab the end

// var pattern + when guards in switches
string Rate(Student st) => st switch
{
    { Gpa: >= 3.9, Year: >= 3 } => "summa candidate",
    { Gpa: >= 3.5 } and { Courses.Count: >= 4 } => "honors track",
    var other when other.Courses.Contains("CS") => "cs cohort",

};
```

## `yield return`: write your own sequences

The machinery LINQ is built on — a method that produces elements lazily, state machine generated by the compiler:

```csharp
static IEnumerable<int> Fibonacci()
{
    int a = 0, b = 1;
    while (true)
    {
        yield return a;
        (a, b) = (b, a + b);
    }
}

var first10 = Fibonacci().Take(10).ToList();    // infinite sequence, finite consumption
```

Execution is pull-based: each `MoveNext` runs *until the next yield*. Combine with `Take`, `TakeWhile` and friends for elegant generators — and understand that this is exactly how `Where`/`Select` are implemented.

```csharp
public record LogEntry(string Level, DateTime At, string Source, string Message);

static LogEntry? Parse(string line)
    => line.Split(' ', 4) is [var level, var ts, var source, var message]
        && DateTime.TryParse(ts, out var at)
        && level is "ERROR" or "WARN" or "INFO" or "DEBUG"
        ? new LogEntry(level, at, source, message)
        : null;
```

One expression: list pattern demands exactly 4 parts, binds all four, guards validate. Compare with the if-ladder you'd have written in Module 2 — same logic, half the code, no intermediate state.

### Step 3 — classify with nested property patterns

```csharp
static string Triage(LogEntry e) => e switch
{
    { Level: "ERROR", Message: var m } when m.Contains("Deadlock") => "🔴 PAGE THE DBA",
    { Level: "ERROR", Source: var s } when s.StartsWith("db") => "🟠 database incident",
    { Level: "ERROR" } => "🟠 investigate",
```

### Step 4 — a yield-based sliding window

Detect error bursts (2+ errors within 5 minutes) using a custom generator:

```csharp
static IEnumerable<(LogEntry A, LogEntry B)> Pairs(IEnumerable<LogEntry> entries)
{
    LogEntry? prev = null;
    foreach (var e in entries)
    {
        if (prev is not null) yield return (prev, e);
        prev = e;
    }
}

var errors = logLines.Select(Parse)
    .OfType<LogEntry>()                                   // filters nulls AND narrows the type
    .Where(e => e.Level == "ERROR");

foreach (var (a, b) in Pairs(errors))
    if (b.At - a.At is { TotalMinutes: <= 5 })
        Console.WriteLine($"⚠ error burst: {a.At:HH:mm} + {b.At:HH:mm} on {b.Source}");
```

Note `OfType<LogEntry>()` — the cleanest way to drop nulls from a `LogEntry?` sequence, and a property pattern on a TimeSpan.

## Challenge: `tiny-json` — a JSON shape validator with patterns

Without any JSON library, validate a *token list* representing simplified JSON using list patterns and recursion. (Real parsing comes in Module 6; this kata is about pattern fluency.)

Tokens: `{`, `}`, `[`, `]`, `:`, `,`, strings (any token starting with `"`), numbers (parseable), `true`, `false`, `null`.

### Requirements

1. `static bool IsValue(string token)` — single-token values: string, number, `true|false|null` — one pattern expression using `or`, a `when`-free approach preferred (hint: `double.TryParse` needs a guard or helper).
2. `static bool IsFlatArray(string[] tokens)` — matches `[` value (`,` value)* `]` or `[ ]`. Use list patterns for the frame (`["[", .. var inner, "]"]`) and then validate `inner` (alternating values and commas — an index loop or chunking is fine inside).
3. `static bool IsFlatObject(string[] tokens)` — `{` string `:` value (`,` string `:` value)* `}` or `{ }`. Same approach: list pattern for the frame, validate inner segments in `Chunk(4)`-ish steps or a loop with patterns per position.
4. Test table (at least): `["[", "]"]` ✔; `["[", "1", ",", "2", "]"]` ✔; `["[", "1", "2", "]"]` ✘; `["{", "\"a\"", ":", "1", "}"]` ✔; `["{", "\"a\"", "1", "}"]` ✘; `["{", "}"]` ✔.
5. Every branch decision must be a pattern (`is`/`switch`), not `==` chains — grep your file for `== "` and justify any hit.

:::solution Show solution
```csharp
static bool IsValue(string token) => token switch
{
    ['"', ..] => true,                                    // list pattern ON THE STRING's chars!
    "true" or "false" or "null" => true,
    _ => double.TryParse(token, System.Globalization.CultureInfo.InvariantCulture, out _)
};

static bool IsFlatArray(string[] tokens) => tokens switch
{
    ["[", "]"] => true,
    ["[", .. var inner, "]"] => AlternatesValuesAndCommas(inner),
    _ => false
};

static bool AlternatesValuesAndCommas(string[] inner)
{
    for (int i = 0; i < inner.Length; i++)
    {
        bool ok = (i % 2, inner[i]) switch
        {
            (0, var t) => IsValue(t),                     // even positions: values
            (1, ",") => true,                             // odd positions: commas
            _ => false
        };
        if (!ok) return false;
    }
    return inner.Length % 2 == 1;                         // must END on a value
}

static bool IsFlatObject(string[] tokens) => tokens switch
{
    ["{", "}"] => true,
    ["{", .. var inner, "}"] => ValidObjectBody(inner),
    _ => false
};

static bool ValidObjectBody(string[] inner)
{
    // body = key : value (, key : value)*  → length must be 3, 7, 11, … (4k+3)
    if (inner.Length % 4 != 3) return false;
    for (int i = 0; i < inner.Length; i++)
    {
        bool ok = (i % 4, inner[i]) switch
        {
            (0, ['"', ..]) => true,                       // keys are strings
            (1, ":") => true,
            (2, var t) => IsValue(t),
            (3, ",") => true,
            _ => false
        };
        if (!ok) return false;
    }
    return true;
}

(string, string[] , bool)[] tests =
[
    ("empty array", ["[", "]"], true),
    ("two items", ["[", "1", ",", "2", "]"], true),
    ("missing comma", ["[", "1", "2", "]"], false),
    ("simple object", ["{", "\"a\"", ":", "1", "}"], true),
    ("object missing colon", ["{", "\"a\"", "1", "}"], false),
    ("empty object", ["{", "}"], true),
    ("bool value", ["[", "true", ",", "null", "]"], true),
];

foreach (var (name, tokens, expected) in tests)
{
    bool actual = tokens[0] == "[" ? IsFlatArray(tokens) : IsFlatObject(tokens);
    Console.WriteLine($"{(actual == expected ? "✔" : "✘ FAIL")} {name}");
}
```

The showpiece: `['"', ..]` — list patterns work on strings (they're char sequences), so "starts with a quote" is a pattern, not StartsWith. Position-based validation via `(i % k, token)` tuple switches turns grammar rules into tables. (The `tokens[0] == "["` dispatch in the test loop is a fair "justified hit" for requirement 5 — or patternize it too.)

? `if (result is { } value)` checks…

* That result is not null, binding the non-null value
- That result has no properties
- Reference equality with a default instance

- The array has more than two elements
* The array is empty
- rest would be null
> One element is fine (rest = empty). The pattern needs at least the head to exist — empty arrays don't match.

? What does `yield return` fundamentally change about a method?
- It makes the method async
* The compiler rewrites it into a lazily-evaluated state machine producing elements on demand
- It returns all values at once in a list
- It requires recursion
> Iterator methods run incrementally — each MoveNext executes until the next yield. Infinite sequences and streaming pipelines fall out naturally; LINQ is built on this.

? `using Point = (double X, double Y);` is…
- A tuple declaration
* A type alias (C# 12 allows aliasing any type, including tuples)
- A struct definition
- Invalid C#

? Which is NOT something patterns can express?
- Nested property conditions like Customer.Country
- "starts with" on arrays and strings via list patterns
- Ranges like > 0 and <= 100
* Mutating the matched object's properties
