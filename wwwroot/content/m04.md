## Why classes exist

Module 3's gradebook kept parallel lists in sync by discipline. A **class** replaces discipline with structure: data and the operations on it, bundled behind rules you enforce.

```csharp
public class BankAccount
{
    // FIELD — private storage. Convention: _camelCase
    private decimal _balance;

    // PROPERTY — controlled public access
    public decimal Balance => _balance;                  // read-only, expression-bodied

    public string Owner { get; }                         // get-only: set once in constructor

    public string Nickname { get; set; } = "main";       // auto-property with default

    // CONSTRUCTOR — how instances are born valid
    public BankAccount(string owner, decimal openingBalance = 0)
    {
        if (string.IsNullOrWhiteSpace(owner))
            throw new ArgumentException("Owner required", nameof(owner));
        Owner = owner;
        _balance = openingBalance;
    }

    // METHODS — behavior that keeps the data valid
    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
    }

    public bool TryWithdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance) return false;
        _balance -= amount;
        return true;
    }
}
```

```csharp
var acct = new BankAccount("Ada", 100m);
acct.Deposit(50m);
// acct._balance = 1_000_000m;   // ❌ private — the compiler defends your invariants
```

This is **encapsulation**: `_balance` can *never* be negative because every path that touches it lives in this file. That guarantee is the entire point.

## Properties — the C# power feature

Properties look like fields but run code. The forms, from simplest up:

```csharp
public string Name { get; set; }                   // auto-property (compiler makes hidden field)
public string Name { get; init; }                  // settable ONLY during object initialization
public required string Name { get; init; }         // 'required': compiler forces callers to set it
public string Name { get; private set; }           // public read, class-only write

// C# 14 'field' keyword — accessor logic without a manual backing field:
public string Name
{
    get;
    set => field = value?.Trim() ?? throw new ArgumentNullException(nameof(value));
}

// Computed property — no storage at all:
public bool IsOverdrawn => Balance < 0;
```

### Object initializers pair with init/required

```csharp
public class Order
{
    public required string Product { get; init; }
    public required int Quantity { get; init; }
    public string? Note { get; init; }
}

var order = new Order { Product = "Espresso", Quantity = 2 };   // omit Product → compile error
```

This gives constructor-grade safety with named, any-order syntax — the modern C# way to build data objects.

## Primary constructors (C# 12+)

For classes whose constructor just captures parameters, put the parameters on the class line:

```csharp
public class OrderService(IPaymentGateway gateway, ILogger logger)
{
    public void Checkout(Order order)
    {
        logger.Log($"charging {order.Quantity} x {order.Product}");
        gateway.Charge(order);
    }
}
```

`gateway` and `logger` are in scope throughout the class body. You'll see this constantly in ASP.NET Core dependency injection (Module 10).

## `static` — belongs to the type

```csharp
public class Invoice
{
    private static int _nextNumber = 1;              // ONE copy shared by all instances
    public int Number { get; } = _nextNumber++;
    public static int TotalIssued => _nextNumber - 1;
}
```

Static members are called on the type: `Invoice.TotalIssued`. A `static class` (like `Math` or your Module 2 helpers) can *only* hold static members. Use static for genuinely instance-free logic — overusing it is how you end up with untestable code (Module 8 explains why).

## `this`, `ToString`, and object identity

```csharp
public override string ToString() => $"{Owner}: {Balance:C}";   // every type inherits ToString from object
```

Interpolation and `Console.WriteLine` call `ToString()` automatically — override it on every domain class; debugging quality-of-life is enormous.

Two `BankAccount` objects with identical values are still **different objects** (`==` compares references for classes by default). Records (lesson 4) flip that default.

### Step 1 — the class

Create `Student.cs` (one type per file is the convention):

```csharp
namespace Students;

public class Student
{
    private readonly List<int> _scores = [];

    public required string Name { get; init; }
    public IReadOnlyList<int> Scores => _scores;          // expose read-only view, never the list itself!
    public double? Average => _scores.Count > 0 ? _scores.Average() : null;
    public int Best => _scores.Count > 0 ? _scores.Max() : 0;

    public void Record(int score)
    {
        if (score is < 0 or > 100)
            throw new ArgumentOutOfRangeException(nameof(score), "0–100 only");
        _scores.Add(score);
    }

    public override string ToString()
        => $"{Name,-8} [{string.Join(", ", _scores)}] avg {Average?.ToString("F1") ?? "—"}";
}
```

Read the design choices: the list is `private readonly` (the *reference* can't be replaced; contents managed only via `Record`); the public surface is `IReadOnlyList` so no caller can `.Add(999)` behind your back; validation lives in exactly one place.

### Step 2 — use it

`Program.cs`:

```csharp

    new() { Name = "Grace" },
    new() { Name = "Anders" },
};

students[0].Record(88);
students[1].Record(91);

foreach (var s in students)
    Console.WriteLine(s);                       // ToString() does the work

// invariants hold:
try { students[2].Record(150); }
catch (ArgumentOutOfRangeException e) { Console.WriteLine($"Blocked: {e.ParamName}"); }
```

## Challenge: design `Playlist` and `Track`

Model a music playlist with proper encapsulation. No inheritance needed yet — this is a pure encapsulation kata.

### Requirements

1. `Track`: required init properties `Title`, `Artist`; `Duration` as `TimeSpan`; override `ToString` as `"Title — Artist (m:ss)"` (format the seconds with `:D2` zero-padding… careful: `TimeSpan` needs `@"m\:ss"` custom format or manual composition).
2. `Playlist` with:
   - required `Name`
   - private `List<Track>` exposed as `IReadOnlyList<Track> Tracks`
   - `TotalDuration` computed property summing track durations (start from `TimeSpan.Zero`)
   - `Add(Track track)` rejecting *duplicate title+artist pairs* (case-insensitive) with a `bool` return
   - `bool Remove(string title)`, removing the first title match
   - `Track? Longest` computed property (null when empty)
   - `Shuffle()` that reorders the private list (Fisher–Yates with `Random.Shared`) — internal mutation is fine, that's the class's own business
3. In `Program.cs`: build a playlist of 5 tracks, demonstrate the duplicate rejection, print all tracks numbered, print total + longest, shuffle and print again.

:::solution Show solution
```csharp
public class Track
{
    public required string Title { get; init; }
    public required string Artist { get; init; }
    public TimeSpan Duration { get; init; }

    public override string ToString()
        => $"{Title} — {Artist} ({(int)Duration.TotalMinutes}:{Duration.Seconds:D2})";
}

public class Playlist
{
    private readonly List<Track> _tracks = [];

    public required string Name { get; init; }
    public IReadOnlyList<Track> Tracks => _tracks;

    public TimeSpan TotalDuration
        => _tracks.Aggregate(TimeSpan.Zero, (sum, t) => sum + t.Duration);

    public Track? Longest
        => _tracks.Count == 0 ? null : _tracks.MaxBy(t => t.Duration);

    public bool Add(Track track)
    {
        bool duplicate = _tracks.Any(t =>
            t.Title.Equals(track.Title, StringComparison.OrdinalIgnoreCase) &&
            t.Artist.Equals(track.Artist, StringComparison.OrdinalIgnoreCase));
        if (duplicate) return false;
        _tracks.Add(track);
        return true;
    }

    public bool Remove(string title)
    {
        int i = _tracks.FindIndex(t => t.Title.Equals(title, StringComparison.OrdinalIgnoreCase));
        if (i == -1) return false;
        _tracks.RemoveAt(i);
        return true;
    }

    public void Shuffle()
    {
        for (int i = _tracks.Count - 1; i > 0; i--)
        {
            int j = Random.Shared.Next(i + 1);
            (_tracks[i], _tracks[j]) = (_tracks[j], _tracks[i]);
        }
    }
}
```

```csharp
var mix = new Playlist { Name = "Focus Mix" };
mix.Add(new Track { Title = "Weightless", Artist = "Marconi Union", Duration = new(0, 8, 9) });
mix.Add(new Track { Title = "Intro", Artist = "The xx", Duration = new(0, 2, 7) });
mix.Add(new Track { Title = "Time", Artist = "Hans Zimmer", Duration = new(0, 4, 35) });
mix.Add(new Track { Title = "Avril 14th", Artist = "Aphex Twin", Duration = new(0, 2, 5) });
mix.Add(new Track { Title = "Gymnopédie No.1", Artist = "Erik Satie", Duration = new(0, 3, 21) });

bool dup = mix.Add(new Track { Title = "TIME", Artist = "hans zimmer", Duration = new(0, 4, 35) });
Console.WriteLine($"Duplicate accepted? {dup}");                       // False

for (int i = 0; i < mix.Tracks.Count; i++)
    Console.WriteLine($"{i + 1}. {mix.Tracks[i]}");
Console.WriteLine($"Total {(int)mix.TotalDuration.TotalMinutes}:{mix.TotalDuration.Seconds:D2}  Longest: {mix.Longest}");

mix.Shuffle();
Console.WriteLine("\nAfter shuffle:");
foreach (var t in mix.Tracks) Console.WriteLine($"   {t}");
```

Notes: `Aggregate` folds a sequence with a seed (LINQ, Module 5); `MaxBy` picks the element with the max key; `Random.Shared` is the thread-safe shared instance — no need to construct your own.
:::

@QUIZ
? What problem does encapsulation actually solve?
- It makes code shorter
* Invariants (like "balance never negative") are enforced in one place, so no external code can create invalid state
- It speeds up property access
- It hides code from other developers for licensing
> Private state + validated public operations means the type's rules cannot be bypassed. Every bug of the form "who set this to -5?!" is an encapsulation failure.

? `public string Name { get; init; }` means…
- Name can never be set at all
* Name can be set only during construction/object initialization, then becomes read-only
- Name is private
- Name has no backing storage
> init-only setters permit `new T { Name = ... }` and constructor assignment, then freeze. Pair with `required` to make setting mandatory.

? Why expose `IReadOnlyList<Track>` instead of `List<Track>`?
- It's faster
- It saves memory
* Callers can read/iterate but cannot Add/Remove — mutations must go through your validated methods
- Lists cannot be public in C#
> Returning the raw List hands out your internals; any caller could bypass your rules. The read-only interface keeps the mutation surface exactly where you control it.

? What does the C# 14 `field` keyword do?
- Declares a public field
* Refers to the compiler-generated backing field inside a property accessor, so you can add logic without declaring `_name` manually
- Makes a property static
- Creates a thread-safe property
> `set => field = Normalize(value);` gives you accessor logic while the compiler still owns the storage — the missing middle between auto-properties and full manual ones.

? A static member…
- Is copied into every instance
* Belongs to the type itself — one shared copy, accessed as TypeName.Member
- Cannot be private
- Is thread-safe automatically
> Statics are per-type, not per-instance. Shared mutable statics need care with threading (Module 7) — one more reason to prefer instance state.

## Inheritance: "is-a" with shared machinery

A derived class inherits every member of its base and can add or specialize:

```csharp
public class Shape                              // base class
{
    public string Name { get; init; } = "shape";
    public virtual double Area => 0;            // 'virtual' = derived classes MAY override
    public override string ToString() => $"{Name}: {Area:F2}";
}

public class Circle : Shape                     // Circle IS-A Shape
{
    public required double Radius { get; init; }
    public override double Area => Math.PI * Radius * Radius;   // 'override' replaces the base version
}

public class Rectangle : Shape
{
    public required double Width { get; init; }
    public required double Height { get; init; }
    public override double Area => Width * Height;
}
```

## Polymorphism: the payoff

One variable of the base type can hold *any* derived instance — and calls resolve to the **runtime** type:

```csharp
List<Shape> shapes =
[
    new Circle { Name = "wheel", Radius = 0.5 },
    new Rectangle { Name = "door", Width = 0.9, Height = 2.1 },
];

foreach (Shape s in shapes)
    Console.WriteLine(s.Area);      // 0.785…, then 1.89 — each object answers as itself
```

The `foreach` doesn't know or care which concrete shapes exist. You can add `Triangle` next year and this loop keeps working unchanged — that's the **open/closed principle**: open for extension, closed for modification.

### How it works: virtual dispatch

Each class carries a method table. A call to a `virtual` member looks up the *actual object's* table at runtime. Non-virtual calls bind at compile time. (This lookup is what the JIT's devirtualization optimizes away when it can prove the concrete type — Module 1's dynamic PGO in action.)

## Abstract: base classes that can't exist alone

Often a base is only a concept — no sensible default `Area` exists. Make it `abstract`:

```csharp
public abstract class Shape
{
    public string Name { get; init; } = "shape";
    public abstract double Area { get; }               // no body — MUST be overridden
    public double PricePerM2(decimal rate) => ...      // concrete shared logic lives happily beside
}

// var s = new Shape();          // ❌ cannot instantiate an abstract class
```

Abstract = "I define the contract and some shared machinery; concrete children fill the gaps." This is the **template method** pattern in miniature.

### The modifier trio

| Keyword | On base member | Meaning |
|---------|---------------|---------|
| `virtual` | has a body | derived may override |
| `abstract` | no body | derived must override (class must be abstract too) |
| `sealed` | on override or class | stops further overriding / inheriting |

`sealed class` is a fine default for classes not designed for inheritance — it documents intent and helps the JIT devirtualize.

## Construction order & `base`

```csharp
public class Vehicle
{
    public string Plate { get; }
    public Vehicle(string plate) => Plate = plate;
}

public class Truck : Vehicle
{
    public double MaxLoadTons { get; }
    public Truck(string plate, double maxLoad) : base(plate)   // base ctor runs FIRST
        => MaxLoadTons = maxLoad;
}
```

`base.Method()` also lets an override *extend* rather than replace: do the base work, then add yours.

## Type tests: `is`, casts, and patterns

```csharp
foreach (Shape s in shapes)
{
    // Modern: type pattern with binding
    if (s is Circle c && c.Radius > 1)
        Console.WriteLine($"big circle: {c.Name}");

    // switch on type:
    string desc = s switch
    {
        Circle { Radius: < 0.1 } => "tiny circle",
        Circle => "circle",
        Rectangle r when r.Width == r.Height => "square!",
        _ => "other shape"
    };
}
```

Avoid the old `(Circle)s` hard cast unless you've already proven the type — a wrong cast throws `InvalidCastException`. `as` yields null instead, but `is`-patterns have largely replaced both.

:::warn Inheritance is a loaded gun
Rule of thumb from the .NET design guidelines: **prefer composition over inheritance** for code reuse; inherit only for genuine is-a polymorphism. Deep hierarchies (3+ levels) are a maintenance tar pit. If you're inheriting just to share helpers, a private field of another type ("has-a") is usually righter. Interfaces (next lesson) provide polymorphism without any of these costs.
:::

## Tutorial: a notification system

Project `Notify`. Real-world shape: one pipeline, many delivery channels.

### Step 1 — the abstract base

```csharp
public abstract class Notification
{
    public required string Recipient { get; init; }
    public required string Message { get; init; }
    public DateTimeOffset CreatedAt { get; } = DateTimeOffset.UtcNow;

    public abstract string Channel { get; }
    public abstract decimal CostCents { get; }

    // Template method: shared workflow calling abstract pieces
    public void Send()
    {
        Console.WriteLine($"[{Channel}] to {Recipient} ({CostCents / 100:C}): {Render()}");
    }

    protected virtual string Render() => Message;      // 'protected': visible to derived classes only
}
```

### Step 2 — three channels

```csharp
public class EmailNotification : Notification
{
    public string Subject { get; init; } = "(no subject)";
    public override string Channel => "EMAIL";
    public override decimal CostCents => 0.1m;
    protected override string Render() => $"Subject: {Subject} — {Message}";
}

public class SmsNotification : Notification
{
    public override string Channel => "SMS";
    public override decimal CostCents => 5.0m;
    protected override string Render()
        => Message.Length <= 160 ? Message : Message[..157] + "…";     // SMS truncation rule
}

public sealed class PushNotification : Notification
{
    public override string Channel => "PUSH";
    public override decimal CostCents => 0.01m;
}
```

Each subclass encodes *its own* rules; the base owns the workflow. Note `sealed` on Push — nobody should extend it further.

### Step 3 — the polymorphic pipeline

```csharp
List<Notification> outbox =
[
    new EmailNotification { Recipient = "ada@example.com", Subject = "Welcome", Message = "Glad you joined!" },
    new SmsNotification  { Recipient = "+62811111", Message = new string('x', 200) },
    new PushNotification { Recipient = "device:abc", Message = "Build finished ✔" },
];

decimal totalCost = 0;
foreach (var n in outbox)
{
    n.Send();
    totalCost += n.CostCents;
}
Console.WriteLine($"Total spend: {totalCost / 100:C4}");
```

Run it. The loop is five lines and will never change again, no matter how many channels you add. Add a `WhatsAppNotification` yourself right now — feel how *nothing else* needs touching.

### Step 4 — pattern-match for a channel report

```csharp
var summary = outbox
    .GroupBy(n => n.Channel)
    .Select(g => $"{g.Key}: {g.Count()}");
Console.WriteLine(string.Join("  ", summary));

foreach (var n in outbox)
{
    string note = n switch

        SmsNotification { Message.Length: > 160 } => "was truncated",

```

## Challenge: employee payroll hierarchy

Model a payroll run for: salaried employees (fixed monthly), hourly employees (rate × hours, 1.5× over 160h), and contractors (fixed day rate × days, plus they are *not* eligible for the 5% company bonus employees get this quarter).

### Requirements

1. Abstract base `Worker` with `required string Name`, abstract `decimal GrossPay { get; }`, virtual `decimal Bonus => GrossPay * 0.05m`, and sealed method `string PaySlip()` producing a consistent one-line slip: name, type, gross, bonus, net (gross+bonus). The slip must work for every subtype without overrides — template method again.
2. `Salaried(decimal monthly)`, `Hourly(decimal rate, double hours)`, `Contractor(decimal dayRate, int days)` — use primary constructors or regular ones; your choice. Contractor overrides `Bonus` to 0 and *seals* the override.
3. A `List<Worker>` payroll run printing all slips + totals. Then a pattern-matching audit: list anyone whose Bonus is 0, and any Hourly worker who exceeded 160 hours (show the overtime hours).
4. Bonus rule change drill: management says salaried bonus rises to 8%. Which single member changes? Make the change; confirm nothing else touched.

:::solution Show solution
```csharp
public abstract class Worker
{
    public required string Name { get; init; }
    public abstract decimal GrossPay { get; }
    public virtual decimal Bonus => GrossPay * 0.05m;

    public string PaySlip()
        => $"{Name,-10} {GetType().Name,-10} gross {GrossPay,10:C} bonus {Bonus,8:C} net {GrossPay + Bonus,10:C}";
}

public class Salaried : Worker
{
    public required decimal Monthly { get; init; }
    public override decimal GrossPay => Monthly;
    public override decimal Bonus => GrossPay * 0.08m;      // the ONE line for requirement 4
}

public class Hourly : Worker
{
    public required decimal Rate { get; init; }
    public required double Hours { get; init; }
    public double Overtime => Math.Max(0, Hours - 160);

    public override decimal GrossPay
        => (decimal)Math.Min(Hours, 160) * Rate + (decimal)Overtime * Rate * 1.5m;
}

public class Contractor : Worker
{
    public required decimal DayRate { get; init; }
    public required int Days { get; init; }
    public override decimal GrossPay => DayRate * Days;
    public sealed override decimal Bonus => 0m;             // sealed: nobody re-adds a bonus below us
}
```

```csharp
List<Worker> payroll =
[
    new Salaried { Name = "Ada", Monthly = 9000m },
    new Hourly { Name = "Grace", Rate = 40m, Hours = 172 },
    new Hourly { Name = "Linus", Rate = 35m, Hours = 140 },
    new Contractor { Name = "Mads", DayRate = 800m, Days = 15 },
];

foreach (var w in payroll) Console.WriteLine(w.PaySlip());
Console.WriteLine($"{"TOTAL",-21} {payroll.Sum(w => w.GrossPay + w.Bonus),10:C}");

Console.WriteLine("\nAudit:");
foreach (var w in payroll)
{
    switch (w)
    {
        case { Bonus: 0m }:
            Console.WriteLine($"  {w.Name}: no bonus (contractor rules)");
            break;
        case Hourly { Overtime: > 0 } h:
            Console.WriteLine($"  {h.Name}: {h.Overtime}h overtime at 1.5x");
            break;
    }
}
```

Requirement 4's answer: only `Salaried.Bonus` changes — the slip, totals, audit, and every other class are untouched. When a rule change maps to one member, your hierarchy is carved correctly; when it forces edits in five places, the design is telling you something.
:::

@QUIZ
? A `List<Shape>` holds Circles and Rectangles. Calling `s.Area` in a loop returns each shape's own area because…
- The list stores the areas precomputed
* Area is virtual/abstract: calls dispatch to the runtime type's override via its method table
- The compiler generates an if/else over all known types
- C# uses duck typing
> Virtual dispatch consults the actual object's method table at runtime. The static type (Shape) only determines *what you may call*, not *whose code runs*.

? `abstract` members differ from `virtual` members how?
- Abstract members are faster
* Abstract members have no implementation and MUST be overridden; virtual members have one and MAY be
- Virtual members can't access fields
- There's no difference
> abstract = contract only (and makes the class uninstantiable); virtual = default behavior open to specialization.

? When is inheritance the WRONG tool?
- When two classes share an is-a relationship
- When you need polymorphic dispatch
* When you only want to reuse some helper code from another class
- When the base is abstract
> Reuse-by-inheritance couples you to a base's internals forever. Composition (hold a private instance, delegate to it) reuses without the coupling. Inherit for is-a + polymorphism, compose for has-a.

? What does `: base(plate)` in a constructor do?
- Copies the base class's fields

## What an interface is

An **interface** declares capability — *what* a type can do, nothing about *how*:

```csharp
public interface IShippable
{
    decimal WeightKg { get; }
    decimal ShippingCost(string region);
}

public class Book : IShippable
{
    public required string Title { get; init; }
    public decimal WeightKg => 0.4m;
    public decimal ShippingCost(string region) => region == "domestic" ? 2m : 9m;
}

public class Furniture : IShippable { /* its own answers */ }
```

Any type claiming `IShippable` must supply the members — enforced at compile time. Now shipping code works with *anything shippable*:

```csharp
decimal QuoteCart(IEnumerable<IShippable> items, string region)
    => items.Sum(i => i.ShippingCost(region));
```

### Interfaces vs base classes — the real differences

| | Base class | Interface |
|---|-----------|-----------|
| How many can a type have? | exactly one | **any number** |
| Carries state (fields)? | yes | no (contract only) |
| Relationship | is-a (identity) | can-do (capability) |
| Coupling | strong | minimal |

A `Drone` might be `IFlyable`, `IChargeable`, and `ITrackable` — three capabilities no single inheritance chain could express. This is why modern C# leans hard on interfaces: **program to contracts, not implementations.**

### Naming and granularity

Convention: `I` + capability (`IComparable`, `IDisposable`, `ILogger`). Keep interfaces *small* — the **interface segregation principle**: many focused contracts beat one fat one. An interface with one method is perfectly respectable (`IDisposable` runs the world).

## The BCL interfaces you already use

```csharp
public class Money : IComparable<Money>, IEquatable<Money>
{
    public decimal Amount { get; init; }
    public string Currency { get; init; } = "USD";

    public int CompareTo(Money? other) => Amount.CompareTo(other?.Amount ?? 0);
    public bool Equals(Money? other) => other is not null && Amount == other.Amount && Currency == other.Currency;
}
```

- `IComparable<T>` → enables `list.Sort()`, `Max()`, ordering.
- `IEquatable<T>` → efficient equality; pairs with `GetHashCode` for dictionary keys.
- `IEnumerable<T>` → foreach-ability; the substrate of LINQ (Module 5).
- `IDisposable` → deterministic cleanup with `using` (Module 6).
- `IComparer<T>` / `EqualityComparer<T>` — *external* comparison strategies you pass to sorts and dictionaries.

## Decoupling: the architectural superpower

The seed of everything in Modules 8–11. Compare:

```csharp
// ❌ Welded to the console — untestable, unreusable
public class ReportService
{
    public void Generate() => Console.WriteLine("report…");
}

// ✅ Depends on a contract

Tests hand it a fake `IOutput` that records calls (Module 8); production hands it a file or console; tomorrow, a network stream — zero changes to `ReportService`. **This one pattern — depend on interfaces, inject implementations — is the backbone of all modern .NET architecture.**

## Challenge: a payment method system

Build checkout that accepts many payment methods and demonstrates capability-based design.

### Requirements

1. Interface `IPaymentMethod`: `string DisplayName { get; }`, `bool TryPay(decimal amount, out string receiptId)`.
2. Separate interface `IRefundable`: `bool Refund(string receiptId, decimal amount)`. **Not** every method supports refunds.
3. Implementations:
   - `CardPayment` (has `Last4` digits; always pays; refundable)
   - `WalletPayment` (has `Balance`; pays only when balance suffices, deducting on success; refundable — refunds return to balance)
   - `CryptoPayment` (always pays; **not** refundable — do not implement IRefundable)
   - Receipt IDs: any unique string (`Guid.NewGuid().ToString("N")[..8]`).
4. Checkout flow over `List<IPaymentMethod>`: attempt a 75.00 charge with each, print success/failure + receipt.
5. Refund audit: iterate the same list and refund every *refundable* payment using an `is` pattern — Crypto must be reported as "non-refundable" without any crash, and WalletPayment's balance must visibly return.
6. Design question to answer in a comment: why is `IRefundable` a separate interface instead of a `bool CanRefund` property on `IPaymentMethod`? (Think: compile-time vs runtime capability discovery.)

:::solution Show solution
```csharp
public interface IPaymentMethod
{
    string DisplayName { get; }
    bool TryPay(decimal amount, out string receiptId);
}

public interface IRefundable
{
    bool Refund(string receiptId, decimal amount);
}

public class CardPayment : IPaymentMethod, IRefundable
{
    public required string Last4 { get; init; }
    public string DisplayName => $"Card •••• {Last4}";

    public bool TryPay(decimal amount, out string receiptId)
    {
        receiptId = Guid.NewGuid().ToString("N")[..8];
        return true;
    }

    public bool Refund(string receiptId, decimal amount)
    {
        Console.WriteLine($"    card refund {amount:C} → receipt {receiptId}");
        return true;
    }
}

public class WalletPayment : IPaymentMethod, IRefundable
{
    public decimal Balance { get; private set; }
    public WalletPayment(decimal opening) => Balance = opening;
    public string DisplayName => $"Wallet ({Balance:C})";

    public bool TryPay(decimal amount, out string receiptId)
    {
        receiptId = "";
        if (amount > Balance) return false;
        Balance -= amount;
        receiptId = Guid.NewGuid().ToString("N")[..8];
        return true;
    }

    public bool Refund(string receiptId, decimal amount)
    {
        Balance += amount;
        return true;
    }
}

public class CryptoPayment : IPaymentMethod
{
    public string DisplayName => "Crypto (BTC)";
    public bool TryPay(decimal amount, out string receiptId)
    {
        receiptId = Guid.NewGuid().ToString("N")[..8];
        return true;
    }
}
```

```csharp
List<IPaymentMethod> methods =
[
    new CardPayment { Last4 = "4242" },
    new WalletPayment(50m),                     // will FAIL the 75.00 charge
    new WalletPayment(200m),
    new CryptoPayment(),
];

var receipts = new Dictionary<IPaymentMethod, string>();
foreach (var m in methods)
{
    bool ok = m.TryPay(75m, out string receipt);
    Console.WriteLine($"{m.DisplayName,-22} {(ok ? $"✔ paid, receipt {receipt}" : "✘ declined")}");
    if (ok) receipts[m] = receipt;
}

Console.WriteLine("\nRefund audit:");
foreach (var m in methods)
{
    if (!receipts.TryGetValue(m, out string? receipt)) continue;

    if (m is IRefundable r)                      // capability check — the crux of the design
        Console.WriteLine($"{m.DisplayName,-22} refunded: {r.Refund(receipt, 75m)}");
    else
        Console.WriteLine($"{m.DisplayName,-22} non-refundable — needs manual process");
}

// Why a separate interface, not a CanRefund bool?
// A bool moves the contract to runtime: the compiler can't stop you calling Refund()
// on a type that doesn't have one — you'd need Refund() on EVERY method, throwing for
// crypto (a lie in the type system). Separate interfaces mean "supports refunds" is a
// TYPE-LEVEL fact: pattern-match to discover it, impossible to call wrongly.
```
:::

## Structs: your own value types

A `struct` is a type with **value semantics** — copied on assignment, no heap allocation for locals:

```csharp
public readonly struct Point(double X, double Y)   // wait — this is nicer as a record struct; see below
{
    public double X { get; } = X;
    public double Y { get; } = Y;
    public double DistanceTo(Point other)
        => Math.Sqrt(Math.Pow(X - other.X, 2) + Math.Pow(Y - other.Y, 2));
}
```

You've used structs all along: `int`, `DateTime`, `TimeSpan`, `Guid`, `KeyValuePair` — all structs.

### When to define a struct (the design-guideline checklist)

- Represents a single small *value* (a point, a money amount, a range);
- Is ≤ ~16 bytes-ish, immutable, and short-lived in large numbers;
- Otherwise: use a class. **Default to class; structs are an optimization with sharp edges.**

Always prefer **`readonly struct`** — mutable structs are a bug factory (a copy mutates, the original doesn't, and nobody notices which copy they had).

:::note Boxing
Assigning a struct to `object` or a non-generic interface wraps it in a heap box: `object o = 42;` allocates. Unboxing casts it back. Generics exist largely to avoid this — `List<int>` stores raw ints, boxless. Watch for accidental boxing in hot paths (Module 12 measures it).
:::

## Records: data types done for you

A **record** is a class (or struct) where the compiler writes the boring parts — value equality, `ToString`, deconstruction, non-destructive copies:

```csharp
public record Customer(string Name, string Email);   // positional record: one line

var a = new Customer("Ada", "ada@ex.com");
var b = new Customer("Ada", "ada@ex.com");

a == b;                        // TRUE — records compare by VALUE (classes: by reference)
Console.WriteLine(a);          // Customer { Name = Ada, Email = ada@ex.com }  — free ToString
var (name, email) = a;         // free deconstruction

// Non-destructive mutation: 'with' copies, changing only what you name
var moved = a with { Email = "ada@new.com" };
```

Records are still reference types (unless you write `record struct`) — but with value *semantics for equality*. Immutability + `with` is the functional style that makes state changes traceable: nothing mutates, new versions are created.

```csharp
public record struct Money(decimal Amount, string Currency);   // value type + record conveniences
```

### Choosing between them — the 2026 decision table

| You're modeling… | Reach for |
|------------------|-----------|
| A *thing* with identity & lifecycle (User #42 even after renaming) | `class` |
| A *value* defined entirely by its data (an address, a coordinate pair, a DTO) | `record` |
| A tiny performance-critical value in hot loops | `readonly struct` / `record struct` |
| A fixed set of named choices | `enum` |
| A capability contract | `interface` |

DTOs, API payloads, configuration, messages, query results — records everywhere. Records + pattern matching + `with` form modern C#'s functional core.

## Challenge: order lifecycle with records + enums

Model an e-commerce order as an *immutable* record whose lifecycle is enforced by a state machine — the functional style used in real event-driven systems.

### Requirements

1. `enum OrderStatus { Draft, Placed, Paid, Shipped, Delivered, Cancelled }`.
2. `record OrderLine(string Product, int Qty, decimal UnitPrice)` with computed `Total`.
3. `record Order(string Id, OrderStatus Status, ImmutableList-style lines…)` — use `IReadOnlyList<OrderLine>` or a `List` you never mutate; `decimal Total` computed; created via `Order.NewDraft()` factory generating an 8-char id.
4. **Transitions are methods returning new records via `with`**: `AddLine(line)` (Draft only), `Place()` (Draft→Placed, requires ≥1 line), `Pay()` (Placed→Paid), `Ship()` (Paid→Shipped), `Cancel()` (any state except Shipped/Delivered). Illegal transitions throw `InvalidOperationException` with a message naming the states.
5. Use one private helper `Require(OrderStatus expected)` (or a switch) so the rules read declaratively.
6. Demo: walk an order Draft→Delivered printing each version — then prove immutability by showing the original draft is unchanged at the end; and demonstrate one illegal transition being blocked.

:::solution Show solution
```csharp
public enum OrderStatus { Draft, Placed, Paid, Shipped, Delivered, Cancelled }

public record OrderLine(string Product, int Qty, decimal UnitPrice)
{
    public decimal Total => Qty * UnitPrice;
}

public record Order(string Id, OrderStatus Status, IReadOnlyList<OrderLine> Lines)
{
    public static Order NewDraft()
        => new(Guid.NewGuid().ToString("N")[..8], OrderStatus.Draft, []);

    public decimal Total => Lines.Sum(l => l.Total);

    private Order Require(OrderStatus expected, string action)
        => Status == expected ? this
         : throw new InvalidOperationException($"Cannot {action} an order in {Status} (needs {expected}).");

    public Order AddLine(OrderLine line)
        => Require(OrderStatus.Draft, "modify") with { Lines = [.. Lines, line] };

    public Order Place()
        => Lines.Count == 0
            ? throw new InvalidOperationException("Cannot place an empty order.")
            : Require(OrderStatus.Draft, "place") with { Status = OrderStatus.Placed };

    public Order Pay()  => Require(OrderStatus.Placed, "pay") with { Status = OrderStatus.Paid };
    public Order Ship() => Require(OrderStatus.Paid, "ship") with { Status = OrderStatus.Shipped };
    public Order Deliver() => Require(OrderStatus.Shipped, "deliver") with { Status = OrderStatus.Delivered };

    public Order Cancel() => Status is OrderStatus.Shipped or OrderStatus.Delivered
        ? throw new InvalidOperationException($"Too late to cancel: {Status}.")
        : this with { Status = OrderStatus.Cancelled };

    public override string ToString() => $"[{Id}] {Status,-9} {Lines.Count} line(s) {Total,8:C}";
}
```

```csharp
var draft = Order.NewDraft()
    .AddLine(new("espresso", 2, 3.50m))
    .AddLine(new("croissant", 1, 4.25m));
Console.WriteLine(draft);

var placed = draft.Place();
var paid = placed.Pay();
var shipped = paid.Ship();
var delivered = shipped.Deliver();
Console.WriteLine(delivered);

Console.WriteLine($"\noriginal draft untouched: {draft}");        // still Draft — immutability proven

try { shipped.Cancel(); }
catch (InvalidOperationException e) { Console.WriteLine($"blocked: {e.Message}"); }
```

Notes: `[.. Lines, line]` is a collection expression *spread* — new list = old elements + one. Every state is a distinct immutable snapshot; you effectively get an audit trail for free (keep the intermediate variables and you have event sourcing's core idea). Compare mentally with a mutable `order.Status = ...` design, where any code anywhere could corrupt the lifecycle.
:::

> Positional records auto-implement the "data type ceremony": Equals/GetHashCode by value, readable ToString, Deconstruct, and non-destructive with copies. (Plain records are still reference types.)

? `orderA == orderB` is true for two separately-created records with identical data because…
- They're the same object
* Records implement equality by comparing member values, not references
- == always compares values in C#
- The runtime interns records
> Value-based equality is the record's headline feature. For classes, == defaults to reference identity.

? When is a struct the right choice?
- Whenever the type has methods
- For any type used in a List
* For small, immutable, value-like data used in large numbers where allocation pressure matters
- Never; records replaced structs
> The design guidelines: small (≈16 bytes), immutable, logically a single value. Default to class/record; use readonly struct as a deliberate optimization.

? What does `order with { Status = Paid }` do?
- Mutates order's Status
* Creates a copy of order identical except Status — the original is untouched
- Creates a subclass
- Throws if Status is init-only
> with-expressions are non-destructive mutation: clone + selective change. The foundation of immutable domain modeling.

? `[Flags] enum` members use powers of two so that…
- They serialize smaller
* Combinations can be stored in one value via bitwise OR and tested with HasFlag
- The compiler can validate ranges
- Enums can exceed 32 members
> 1, 2, 4, 8… occupy distinct bits, so Cheese|Olives = 5 losslessly encodes both. Non-power values would collide.

## Domain rules (read twice — the code must enforce all of them)

1. Items: **Book** (loan 21 days, reservable), **DVD** (loan 7 days, reservable), **Magazine** (loan 3 days, *not* reservable).
2. Members have tiers: `Standard` (max 3 concurrent loans) and `Premium` (max 7).
3. Checkout fails politely when: item already on loan, member at their limit, or item reserved by *someone else*.
4. A reserved item can only be checked out by its reserver (which consumes the reservation).
5. Returning an item computes late fees: `0.50` per day late (magazines `1.00` — they're time-sensitive).
6. Every action prints a clear confirmation or refusal; the system can list inventory, a member's loans, and overdue items.

## Design guidance (decide before you code)

**Where does state live?** One `Library` class holds the collections (items, members, active loans) and *every* rule. Items don't check members' limits; members don't mutate loans — the aggregate does. This "one guardian of consistency" idea scales all the way up to domain-driven design's aggregates (Module 11).

**What's a Loan?** A record: `(string ItemId, string MemberId, DateOnly Due)` — pure data. *Computing* lateness needs today's date — pass it in (`FeeFor(DateOnly today)`), don't bake `DateTime.Now` into domain logic. Reason: testability — you'll unit-test late fees in Module 8 with fixed dates, no time travel required.

**Why is the loan period on the item type?** Because it *varies by type* — that's textbook polymorphism: `public abstract int LoanDays { get; }`. Same for the fee rate. The `Library` asks the item; it never switches on the item's concrete type. Any `switch (item) { case Book: ... }` inside `Library` is a design smell here — behavior that varies by type belongs *on* the type.

public enum ItemStatus { Available, OnLoan }
public enum Tier { Standard, Premium }

public abstract class LibraryItem
{
    public string Id { get; } = Guid.NewGuid().ToString("N")[..6];
    public required string Title { get; init; }
    public ItemStatus Status { get; internal set; } = ItemStatus.Available;

    public abstract int LoanDays { get; }
    public virtual decimal LateFeePerDay => 0.50m;

    public override string ToString() => $"[{Id}] {GetType().Name,-8} {Title,-30} {Status}";
}

public class Book : LibraryItem
{
    public required string Author { get; init; }
    public override int LoanDays => 21;
}

public class Dvd : LibraryItem
{
    public override int LoanDays => 7;
}

public class Magazine : LibraryItem
{
    public required int IssueNumber { get; init; }
    public override int LoanDays => 3;
    public override decimal LateFeePerDay => 1.00m;
}

public record Member(string Id, string Name, Tier Tier)
{
    public int MaxLoans => Tier == Tier.Premium ? 7 : 3;
}

public record Loan(string ItemId, string MemberId, DateOnly Due)
{
    public decimal FeeFor(LibraryItem item, DateOnly today)
        => today <= Due ? 0m : (today.DayNumber - Due.DayNumber) * item.LateFeePerDay;

### Step 2 — the Library aggregate (first slice)

```csharp
public class Library
{
    private readonly Dictionary<string, LibraryItem> _items = [];
    private readonly Dictionary<string, Member> _members = [];
    private readonly List<Loan> _loans = [];

    public void AddItem(LibraryItem item) => _items[item.Id] = item;
    public void AddMember(Member m) => _members[m.Id] = m;

    public IEnumerable<LibraryItem> Inventory => _items.Values;
    public IEnumerable<Loan> LoansFor(string memberId) => _loans.Where(l => l.MemberId == memberId);

    public string Checkout(string itemId, string memberId, DateOnly today)
    {
        if (!_items.TryGetValue(itemId, out var item)) return "No such item.";
        if (!_members.TryGetValue(memberId, out var member)) return "No such member.";
        if (item.Status == ItemStatus.OnLoan) return $"'{item.Title}' is already on loan.";
        if (LoansFor(memberId).Count() >= member.MaxLoans)
            return $"{member.Name} is at the {member.Tier} limit of {member.MaxLoans}.";

        item.Status = ItemStatus.OnLoan;
        var loan = new Loan(itemId, memberId, today.AddDays(item.LoanDays));
        _loans.Add(loan);
        return $"'{item.Title}' due {loan.Due} for {member.Name}.";
    }

    public string Return(string itemId, DateOnly today)
    {
        var loan = _loans.FirstOrDefault(l => l.ItemId == itemId);
        if (loan is null) return "That item isn't on loan.";

        var item = _items[itemId];
        decimal fee = loan.FeeFor(item, today);
        _loans.Remove(loan);
        item.Status = ItemStatus.Available;

        return fee == 0 ? $"'{item.Title}' returned on time."
                        : $"'{item.Title}' returned {today.DayNumber - loan.Due.DayNumber} days late — fee {fee:C}.";
    }
}
```

@QUIZ
? Loan periods differ per item type. Where does that knowledge belong?
- A switch in Library.Checkout
* An abstract/virtual member on LibraryItem overridden by each type
- A Dictionary&lt;Type,int&gt; in Program.cs
- A constant in each method that needs it
> Behavior that varies by type belongs on the type — that's polymorphism. Central switches over concrete types must be updated for every new type and eventually get missed.

? Why does FeeFor take `DateOnly today` as a parameter instead of using DateTime.Now internally?
- Now is too slow
* Determinism and testability — callers control time, so tests can verify fees for any fixed date
- DateOnly can't read the clock
- To support time zones
> Hidden clock reads make domain logic untestable and irreproducible. Passing time in (or injecting a TimeProvider) is the professional pattern.

? Magazine doesn't implement IReservable. The Reserve method handles this via…
- try/catch around a cast
* `item is not IReservable r` pattern check returning a polite refusal
- A CanReserve bool on every item
- Reflection
> Optional capability = separate interface + pattern check. The compiler makes it impossible to call reservation members on a Magazine.

? All state changes flow through the Library class because…
- Static classes are faster
* One guardian enforces cross-entity rules (limits, reservations) that no single item or member could check alone
- C# requires it
- It reduces file count
> Rules spanning multiple objects need a coordinator that sees all of them — the aggregate pattern. Scattered mutation = unenforceable invariants.
