## Arrays: fixed-size, contiguous, fast

```csharp
int[] scores = new int[5];              // five zeros
int[] primes = { 2, 3, 5, 7, 11 };      // initializer syntax
int[] evens  = [2, 4, 6, 8];            // collection expression (C# 12+) — modern spelling

primes[0] = 13;        // index write
int last = primes[^1]; // ^1 = "one from the end" (index-from-end operator)
int[] mid = primes[1..4];   // range: elements 1,2,3 (end exclusive) — makes a COPY
```

Arrays are a single contiguous block of memory. That gives them the best possible iteration performance (CPU cache loves contiguity) — but the length is **fixed forever** at creation. Useful members: `arr.Length`, `Array.Sort(arr)`, `Array.IndexOf(arr, x)`, `arr.Clone()`.

Multidimensional flavors exist — rectangular `int[,] grid = new int[3, 4]` and jagged `int[][] rows` (array of arrays; rows may differ in length) — you'll mostly meet them in algorithm work.

## `List<T>`: the workhorse

95% of the time you want a **growable** sequence — that's `List<T>` from `System.Collections.Generic`:

```csharp
var tasks = new List<string>();          // empty
var nums  = new List<int> { 1, 2, 3 };   // initializer
List<int> viaExpr = [1, 2, 3];           // collection expression works here too

tasks.Add("learn arrays");               // append — O(1) amortized
tasks.Insert(0, "wake up");              // insert at index — O(n): shifts everything right
tasks.Remove("wake up");                 // first match — O(n) search + shift
tasks.RemoveAt(0);                       // by index — O(n) shift
bool has = tasks.Contains("x");          // O(n) linear scan
int i = tasks.IndexOf("x");              // O(n)
tasks.Count;                             // property, not method (arrays use .Length)
tasks.Sort();                            // in-place
tasks.Clear();
```

### What `<T>` means

`List<T>` is **generic**: `T` is a placeholder filled at compile time. `List<int>` stores ints with no boxing and full type safety — `tasks.Add(42)` on a `List<string>` is a *compile* error. Generics get a full lesson in Module 5; for now: always name the element type.

### How List grows — and why you should care

Internally `List<T>` wraps an array. When full, it allocates a **double-size** array and copies everything over:

```
Capacity: 4 → 8 → 16 → 32 → ...
Count:    how many you actually stored
```

Doubling makes `Add` *amortized O(1)* — occasional expensive copies averaged over many cheap appends. Two practical consequences:

```csharp
var big = new List<int>(capacity: 1_000_000);   // pre-size when you know the count: skips all regrows
```

And: inserting/removing at the **front** of a big list is O(n) every time — if you need cheap front-removal, you want a `Queue<T>` (next lesson).

:::warn Don't modify while foreach-ing
`foreach (var t in tasks) { tasks.Remove(t); }` throws `InvalidOperationException: Collection was modified`. Options: iterate a copy (`tasks.ToList()`), loop backwards by index, or use `tasks.RemoveAll(t => condition)` — the built-in that exists precisely for this.
:::

### Iteration patterns

```csharp
foreach (var t in tasks) Console.WriteLine(t);           // default

for (int j = 0; j < tasks.Count; j++)                    // when you need the index
    Console.WriteLine($"{j + 1}. {tasks[j]}");

tasks.ForEach(Console.WriteLine);                        // List-only convenience
```

## Value semantics reminder

Both arrays and lists are **reference types**: assigning shares the object; `Clone()`/`ToList()` make shallow copies. If elements are themselves reference types, a shallow copy shares the *elements* — a distinction that returns in Module 4.

## Challenge: `Inventory` — a list-backed stock tracker

Build a console inventory for a tiny shop, driven by commands (reuse your Module 2 REPL skills).

### Requirements

1. Two parallel lists: `List<string> items`, `List<int> stock` (yes, parallel on purpose — feel the pain that Dictionary will cure).
2. Commands:
   - `add <name> <qty>` — new item, or add qty if it exists
   - `take <name> <qty>` — reduce stock; refuse to go below 0 with a message showing available amount
   - `low <threshold>` — list items with stock below threshold
   - `report` — all items right-aligned with quantities, plus total units and the single most-stocked item
   - `quit`
3. `report` must use at least one index-based for loop and one `^`/range operation somewhere meaningful.
4. Never crashes on malformed commands (wrong arg counts, non-numeric qty).

:::solution Show solution
```csharp
var items = new List<string>();
var stock = new List<int>();

Console.WriteLine("inventory — add/take/low/report/quit");
while (true)
{
    Console.Write("> ");
    string[] p = (Console.ReadLine() ?? "quit").Trim().Split(' ', StringSplitOptions.RemoveEmptyEntries);
    if (p.Length == 0) continue;

    switch (p[0].ToLowerInvariant())
    {
        case "quit": return;

        case "add" when p.Length == 3 && int.TryParse(p[2], out int addQty) && addQty > 0:
        {
            int i = items.IndexOf(p[1]);
            if (i == -1) { items.Add(p[1]); stock.Add(addQty); }
            else stock[i] += addQty;
            Console.WriteLine($"{p[1]}: {stock[items.IndexOf(p[1])]}");
            break;
        }

        case "take" when p.Length == 3 && int.TryParse(p[2], out int takeQty) && takeQty > 0:
        {
            int i = items.IndexOf(p[1]);
            if (i == -1) { Console.WriteLine($"No item '{p[1]}'."); break; }
            if (stock[i] < takeQty) { Console.WriteLine($"Only {stock[i]} available."); break; }
            stock[i] -= takeQty;
            Console.WriteLine($"{p[1]}: {stock[i]} left");
            break;
        }

        case "low" when p.Length == 2 && int.TryParse(p[1], out int threshold):
            for (int i = 0; i < items.Count; i++)
                if (stock[i] < threshold) Console.WriteLine($"{items[i]} ({stock[i]})");
            break;

        case "report":
        {
            if (items.Count == 0) { Console.WriteLine("(empty)"); break; }
            int total = 0, maxIdx = 0;
            for (int i = 0; i < items.Count; i++)
            {
                Console.WriteLine($"{items[i],-12}{stock[i],5}");
                total += stock[i];
                if (stock[i] > stock[maxIdx]) maxIdx = i;
            }
            Console.WriteLine($"{"TOTAL",-12}{total,5}");
            Console.WriteLine($"Most stocked: {items[maxIdx]} — last added item: {items[^1]}");
            break;
        }

        default:
            Console.WriteLine("Usage: add <name> <qty> | take <name> <qty> | low <n> | report | quit");
            break;
    }
}
```

Note `case "add" when ...` — case guards keep validation beside dispatch. Every mutation keeps both lists aligned; notice how much discipline that requires. Next lesson replaces the pair with one `Dictionary<string, int>` and half this code disappears.
:::

@CHECKS
- Adding an existing item accumulates rather than duplicating
- take refuses to oversell and shows the available amount
- report shows aligned columns, total, most-stocked, and uses ^1 somewhere
- Malformed commands print usage instead of crashing

@QUIZ
? Why is Add on a List O(1) "amortized"?
- Because lists are linked structures
* Most Adds are a simple write; occasionally a double-size regrow copies everything, averaging out to constant time
- Because the compiler optimizes it away
- It's actually O(n) always
> The doubling strategy means n appends do at most ~2n element copies total — constant per append on average. Pre-sizing with a capacity removes even those copies.

? What does `list[^2]` mean?
- Index 2 from the start
* The second element from the end
- A compile error on List
- The list with 2 elements removed
> The ^ index-from-end operator: ^1 is last, ^2 second-to-last. Works on arrays, strings, List, and anything countable.

? You need to remove all even numbers from a List while examining each. Best tool?
- foreach with Remove inside
- while(true) with manual indexes
* RemoveAll with a predicate
- Convert to array first, always
> RemoveAll(n => n % 2 == 0) exists precisely because mutating during foreach throws. It's also O(n) — one pass — vs O(n²) for repeated Remove calls.

? An array vs a List — pick the TRUE statement.
- Lists are contiguous; arrays are linked
* Arrays are fixed-length; List wraps an array and grows by doubling capacity
- Arrays live on the stack, Lists on the heap
- List.Count is O(n)
> Both are heap objects backed by contiguous storage; the difference is fixed vs growable length. Count is a stored field — O(1).

## Dictionary&lt;TKey, TValue&gt;: lookup by key in O(1)

The most important collection after List. A hash table mapping unique keys to values:

```csharp
var stock = new Dictionary<string, int>
{
    ["espresso"] = 12,
    ["croissant"] = 5,
};

stock["bagel"] = 8;              // add or overwrite
int n = stock["espresso"];       // read — THROWS KeyNotFoundException if missing!

// The safe read — burn this into muscle memory:
if (stock.TryGetValue("muffin", out int count))
    Console.WriteLine($"muffin: {count}");
else
    Console.WriteLine("no muffins");

stock.ContainsKey("bagel");      // true
stock.Remove("croissant");
stock.Count;

// GetValueOrDefault: read with fallback, one line
int muffins = stock.GetValueOrDefault("muffin", 0);

// counting things — the classic idiom:
foreach (var word in words)
    counts[word] = counts.GetValueOrDefault(word) + 1;

foreach (var (item, qty) in stock)          // deconstruct KeyValuePair
    Console.WriteLine($"{item}: {qty}");
```

### How hashing works (the 90-second version)

`GetHashCode()` converts a key into an int; the dictionary uses it to jump straight to a *bucket* rather than scanning. That's why lookup is O(1) — and why two rules exist:

1. **Never mutate an object while it's a dictionary key** (its hash would change; it becomes unfindable).
2. Keys must implement `GetHashCode`/`Equals` consistently — free for string, numbers, and records (Module 4).

## HashSet&lt;T&gt;: a bag of unique values

```csharp
var seen = new HashSet<string>();
seen.Add("alice");        // true — added
seen.Add("alice");        // false — already there (no exception, no duplicate)
seen.Contains("alice");   // O(1) — vs O(n) for List.Contains!

var a = new HashSet<int> { 1, 2, 3, 4 };
var b = new HashSet<int> { 3, 4, 5 };
a.IntersectWith(b);       // {3, 4}   also UnionWith, ExceptWith, IsSubsetOf...
```

Any time you write `if (!list.Contains(x)) list.Add(x)` — you wanted a HashSet.

## Queue&lt;T&gt; and Stack&lt;T&gt;

```csharp
var queue = new Queue<string>();     // FIFO — first in, first out
queue.Enqueue("job1");
queue.Enqueue("job2");
string next = queue.Dequeue();       // "job1"
queue.Peek();                        // look without removing

var stack = new Stack<string>();     // LIFO — last in, first out
stack.Push("page1");
stack.Push("page2");
string top = stack.Pop();            // "page2" — undo/back-button semantics
```

Print queues, message processing, breadth-first search → Queue. Undo history, expression evaluation, depth-first search → Stack.

## The decision table (memorize this one)

| Need | Collection | Key ops |
|------|-----------|---------|
| Ordered sequence, index access | `List<T>` | `[i]` O(1), search O(n) |
| Lookup by key | `Dictionary<K,V>` | get/set/remove O(1) |
| Uniqueness / membership tests | `HashSet<T>` | Add/Contains O(1) |
| Process in arrival order | `Queue<T>` | Enqueue/Dequeue O(1) |
| Process most-recent-first | `Stack<T>` | Push/Pop O(1) |
| Always-sorted by key | `SortedDictionary<K,V>` | O(log n) ops |
| Priority-based processing | `PriorityQueue<T,P>` | Enqueue/Dequeue O(log n) |

### Interfaces you'll see everywhere

APIs usually accept/return abstractions rather than concrete types:

- `IEnumerable<T>` — "something you can foreach" (the broadest; powers LINQ).
- `ICollection<T>` — adds Count, Add, Remove.
- `IList<T>` — adds indexing.
- `IReadOnlyList<T>` / `IReadOnlyDictionary<K,V>` — expose data without allowing mutation.

Write methods that *accept* the weakest interface they need (`IEnumerable<T>` if you only foreach) — it makes them usable with arrays, lists, sets, and LINQ results alike. This principle gets formalized in Modules 4–5.

## Challenge: rebuild `Inventory` on Dictionary + extras

Rewrite the previous lesson's inventory the right way, then extend it beyond what parallel lists could reasonably do.

### Requirements

1. Storage is a single `Dictionary<string, int>`. Commands `add`, `take`, `low`, `report`, `quit` work as before (case-insensitive item names: use `new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)`).
2. New: `restock` — prints a shopping list of items with 0 stock as a `HashSet<string>` union with a fixed set of always-stocked staples (e.g. espresso, milk) minus items currently in stock. Use real set operations, not loops.
3. New: `history` — every add/take is recorded; `history` prints the last 5 actions most-recent-first (Stack) and `undo` reverses the most recent action.
4. Compare line counts of add/take with your previous version and note the difference in a comment.

:::solution Show solution
```csharp
var stock = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase);
var actions = new Stack<(string Item, int Delta)>();     // for history + undo
string[] staples = ["espresso", "milk", "sugar"];

Console.WriteLine("inventory2 — add/take/low/report/restock/history/undo/quit");
while (true)
{
    Console.Write("> ");
    string[] p = (Console.ReadLine() ?? "quit").Trim().Split(' ', StringSplitOptions.RemoveEmptyEntries);
    if (p.Length == 0) continue;

    switch (p[0].ToLowerInvariant())
    {
        case "quit": return;

        case "add" when p.Length == 3 && int.TryParse(p[2], out int q) && q > 0:
            stock[p[1]] = stock.GetValueOrDefault(p[1]) + q;      // one line replaces IndexOf dance
            actions.Push((p[1], +q));
            Console.WriteLine($"{p[1]}: {stock[p[1]]}");
            break;

        case "take" when p.Length == 3 && int.TryParse(p[2], out int q) && q > 0:
            if (!stock.TryGetValue(p[1], out int have)) { Console.WriteLine($"No '{p[1]}'."); break; }
            if (have < q) { Console.WriteLine($"Only {have} available."); break; }
            stock[p[1]] = have - q;
            actions.Push((p[1], -q));
            Console.WriteLine($"{p[1]}: {stock[p[1]]} left");
            break;

        case "low" when p.Length == 2 && int.TryParse(p[1], out int t):
            foreach (var (item, qty) in stock)
                if (qty < t) Console.WriteLine($"{item} ({qty})");
            break;

        case "report":
            foreach (var (item, qty) in stock.OrderBy(kv => kv.Key))
                Console.WriteLine($"{item,-12}{qty,5}");
            Console.WriteLine($"{"TOTAL",-12}{stock.Values.Sum(),5}");
            break;

        case "restock":
        {
            var needed = new HashSet<string>(staples, StringComparer.OrdinalIgnoreCase);
            needed.UnionWith(stock.Where(kv => kv.Value == 0).Select(kv => kv.Key));
            needed.ExceptWith(stock.Where(kv => kv.Value > 0).Select(kv => kv.Key));
            Console.WriteLine(needed.Count == 0 ? "Nothing needed."
                                                : $"Buy: {string.Join(", ", needed)}");
            break;
        }

        case "history":
            foreach (var (item, delta) in actions.Take(5))
                Console.WriteLine($"{(delta > 0 ? "+" : "")}{delta} {item}");
            break;

        case "undo":
            if (actions.Count == 0) { Console.WriteLine("Nothing to undo."); break; }
            var last = actions.Pop();
            stock[last.Item] = stock.GetValueOrDefault(last.Item) - last.Delta;
            Console.WriteLine($"Undid {(last.Delta > 0 ? "add" : "take")} of {Math.Abs(last.Delta)} {last.Item}");
            break;

        default:
            Console.WriteLine("add <n> <q> | take <n> <q> | low <t> | report | restock | history | undo | quit");
            break;
    }
}
```

The add command shrank from seven lines to three, and the impossible-to-desync property is structural now: one dictionary can't disagree with itself. Undo via a stack of deltas is a genuinely production-grade pattern (event sourcing in miniature).

## Immutability — the fact that explains everything

A `string` can never change. Every "modifying" method returns a **new** string:

```csharp
string s = "hello";
s.ToUpper();                    // does NOTHING to s (result discarded!)
s = s.ToUpper();                // reassign to capture the new string: "HELLO"
```

Why immutable? Safe sharing across threads, safe use as dictionary keys, interning of literals, no defensive copies. The cost: heavy string *building* creates garbage — which is exactly what `StringBuilder` solves below.

## The everyday toolkit

```csharp
string s = "  .NET Bootcamp 2026  ";

s.Trim();                       // ".NET Bootcamp 2026"   also TrimStart/TrimEnd
s.ToUpperInvariant();           // culture-safe upper (see warning below)
s.Contains("Boot");             // true
s.StartsWith(".NET");           // true (after Trim!)
s.IndexOf("camp");              // 10, or -1 if absent
s.Replace("2026", "2027");      // new string with replacements
s.Substring(2, 4);              // "NET " — start, length
s[2..6];                        // same, with ranges — prefer this
s.Split(' ', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
string.Join(", ", parts);       // inverse of Split
s.PadLeft(30, '·');
string.IsNullOrWhiteSpace(s);   // THE null/empty/spaces check — use constantly
```

### Comparison done right

```csharp
"Straße".Equals("strasse", StringComparison.OrdinalIgnoreCase);   // explicit intent

string.Compare(a, b, StringComparison.Ordinal);                   // sorting
```

:::warn The Turkish-İ problem
`ToLower()`/`ToUpper()` and default comparisons are **culture-sensitive**. In Turkish culture, `"I".ToLower()` is `ı` (dotless), so `"FILE".ToLower() == "file"` is *false*. Rules: for user-facing text use culture-aware; for identifiers, file paths, protocol tokens use `Ordinal`/`OrdinalIgnoreCase` or `ToUpperInvariant`. Analyzer CA1310 exists because real systems break on this.
:::

## StringBuilder: when you build in a loop

Concatenating in a loop is O(n²) — each `+=` copies everything so far into a fresh string:

```csharp
// ❌ 10k iterations → ~50M chars copied, mountains of garbage
string report = "";
for (int i = 0; i < 10_000; i++) report += $"line {i}\n";

// ✅ amortized O(n): one internal growable buffer
var sb = new StringBuilder();
for (int i = 0; i < 10_000; i++) sb.AppendLine($"line {i}");
string done = sb.ToString();
```

`Append`, `AppendLine`, `AppendFormat`, `Insert`, `Length`, and `Clear` cover almost everything. Rule of thumb: two or three `+` concatenations are fine (the compiler optimizes constant folding and `string.Concat`); *loops* build with StringBuilder.

## Chars, Unicode, and encodings (the honest minimum)

- `char` is a **UTF-16 code unit**, not a "character". Emoji and many scripts need two chars (a surrogate pair): `"🚀".Length == 2`.
- Iterate *text elements* safely with `foreach (var rune in s.EnumerateRunes())`.
- Files/networks carry **bytes**; `Encoding.UTF8.GetBytes(s)` / `GetString(bytes)` convert. UTF-8 is the correct default everywhere in 2026.

Char helpers you'll use in parsing: `char.IsDigit(c)`, `char.IsLetter(c)`, `char.IsWhiteSpace(c)`, `char.ToUpperInvariant(c)`.

## Challenge: `slug` — a URL slug generator + CSV parser

Two utilities in one project (`TextTools`), both string-craft classics.

### Part 1 — slugify

`Slugify(string title)` converts titles to URL slugs: `"  10 Tips for C# & .NET (2026 Edition)! "` → `"10-tips-for-c-and-net-2026-edition"`.

Rules: trim; lowercase invariant; `&` becomes `and`; letters/digits kept; every run of anything else collapses to a single `-`; no leading/trailing `-`. Build the result with a StringBuilder in **one pass** over the characters (track "last emitted was a dash" state) — no Regex allowed, that's the exercise.

### Part 2 — parse a CSV line

`ParseCsvLine(string line)` returns `List<string>` for a single CSV line supporting: comma separators, quoted fields containing commas (`"a, b",c` → two fields), and doubled quotes inside quoted fields (`"say ""hi"""` → `say "hi"`). One pass, char by char, with a bool `inQuotes` state and a StringBuilder for the current field. (This is a real state machine — the foundational parsing technique.)

Test data:

```csharp
Console.WriteLine(Slugify("  10 Tips for C# & .NET (2026 Edition)! "));
// 10-tips-for-c-and-net-2026-edition

foreach (var f in ParseCsvLine("name,\"Doe, John\",42,\"say \"\"hi\"\"\""))
    Console.WriteLine($"[{f}]");
// [name] [Doe, John] [42] [say "hi"]
```

:::solution Show solution
```csharp
using System.Text;

static string Slugify(string title)
{
    string t = title.Trim().ToLowerInvariant().Replace("&", " and ");
    var sb = new StringBuilder(t.Length);
    bool lastWasDash = true;                    // true → suppress leading dash

    foreach (char c in t)
    {
        if (char.IsAsciiLetterOrDigit(c))
        {
            sb.Append(c);
            lastWasDash = false;
        }
        else if (!lastWasDash)
        {
            sb.Append('-');
            lastWasDash = true;
        }
    }

    if (sb.Length > 0 && sb[^1] == '-') sb.Length--;   // trim trailing dash: Length is writable!
    return sb.ToString();
}

static List<string> ParseCsvLine(string line)
{
    var fields = new List<string>();
    var current = new StringBuilder();
    bool inQuotes = false;

    for (int i = 0; i < line.Length; i++)
    {
        char c = line[i];

        if (inQuotes)
        {
            if (c == '"')
            {
                if (i + 1 < line.Length && line[i + 1] == '"')   // doubled quote = literal "
                {
                    current.Append('"');
                    i++;                                          // consume the second quote
                }
                else inQuotes = false;                            // closing quote
            }
            else current.Append(c);
        }
        else if (c == '"') inQuotes = true;
        else if (c == ',')
        {
            fields.Add(current.ToString());
            current.Clear();
        }
        else current.Append(c);
    }
    fields.Add(current.ToString());             // last field has no trailing comma
    return fields;
}
```

Both are one-pass state machines: Slugify carries one bit of state (lastWasDash), the CSV parser carries inQuotes plus a lookahead for the doubled-quote escape. Every real parser — JSON, HTTP, compilers — is this pattern scaled up.
:::

## The date/time type family

| Type | What it represents | Example use |
|------|-------------------|-------------|
| `DateTime` | Date + time, with a `Kind` (Utc/Local/Unspecified) | Timestamps (carefully!) |
| `DateTimeOffset` | Date + time + explicit UTC offset | **Best default for moments in time** |
| `DateOnly` | Just a calendar date | Birthdays, due dates |
| `TimeOnly` | Just a clock time | Opening hours, alarms |
| `TimeSpan` | A *duration* | Timeouts, elapsed time |
| `TimeZoneInfo` | A time zone's rules | Converting for display |

```csharp
var now = DateTime.Now;                  // local wall clock
var utc = DateTime.UtcNow;               // UTC — use for storage/logs
var stamp = DateTimeOffset.UtcNow;       // moment + offset: unambiguous

var due = new DateOnly(2026, 8, 1);
var opens = new TimeOnly(9, 30);

var boot = TimeSpan.FromMilliseconds(Environment.TickCount64);
```

:::warn The golden rule
**Store and compute in UTC; convert to local only for display.** Mixing local times across zones/DST is the #1 date bug. `DateTime.Now` in stored data is a smell; `DateTimeOffset.UtcNow` (or `DateTime.UtcNow`) is the professional default.
:::

// Part 1
static (int Years, int Months, int Days) ExactAge(DateOnly birth, DateOnly today)
{
    int years = today.Year - birth.Year;
    int months = today.Month - birth.Month;
    int days = today.Day - birth.Day;

    if (days < 0)
    {
        months--;
        var prevMonth = today.AddMonths(-1);
        days += DateTime.DaysInMonth(prevMonth.Year, prevMonth.Month);
    }
    if (months < 0) { years--; months += 12; }
    return (years, months, days);
}
